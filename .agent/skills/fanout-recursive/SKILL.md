# /fanout:recursive

- 목적: 노드를 처리해야 다음 노드가 나오는 순회형 조사를 레벨별로 돌린다. 방문 기록, 중복 제거, 깊이와 개수 상한은 코드가 관리한다.
- 이 스킬 호출이 곧 Workflow 도구 사용 승인이다.
- 목록을 미리 뽑을 수 있으면 이 스킬이 아니라 `/fanout` 을 쓴다.

## 요청

`$ARGUMENTS`

## 절차

1. 순회 정의 확인
   - 아래 세 가지가 드러나지 않으면 부족한 것을 질문하고 중단한다.
     - 노드가 무엇인가 (파일, 클래스, 토픽, 문서 등)
     - 노드에서 자식을 어떻게 찾는가 (import, 호출, 구독, 링크 등)
     - 노드마다 무엇을 기록하는가

2. 시작 노드 확정
   - Bash 로 시작 노드를 직접 뽑는다. 추측하지 않는다.
   - 시작 노드와 뽑은 명령을 사용자에게 보여 준다.

3. 상한 정하기
   - 사용자가 말하지 않았으면 `maxDepth` 5, `maxNodes` 300 으로 둔다.
   - 예상 노드 수가 상한에 가까우면 실행 전에 알리고 확인한다.

4. 워크플로 실행
   - Workflow 도구를 `name: "traverse"` 로 호출한다.
   - `args`: `{ seeds, prompt, root?, shardSize?, maxDepth?, maxNodes?, maxRounds?, criticRounds? }` 를 JSON 값으로 넘긴다.
   - `prompt` 에는 `{{nodes}}` 자리표시자를 반드시 넣는다. 샤드의 노드가 거기에 들어간다.
   - `prompt` 에 자식을 찾는 규칙을 구체적으로 적는다. 어떤 연결을 따라가고 어떤 연결은 따라가지 않는지 적는다.
   - 노드 이름은 `root` 기준 상대경로처럼 한 가지 표기로 통일하게 한다. 표기가 갈리면 중복 제거가 안 된다.

5. 결과 보고
   - `visitedCount` 를 먼저 말한다.
   - `truncated` 가 있으면 완료라고 말하지 않는다. 상한(`maxDepth`, `maxNodes`)에 걸려 열지 못한 노드를 그대로 보여 준다.
   - `missing` 은 재투입 후에도 처리되지 못한 노드이므로 따로 보여 준다.
   - `criticGaps` 는 마지막 점검에서 나온 놓친 연결이다. 어떤 시작점이 추가돼 다시 돌았는지 함께 말한다.
   - 이 방식은 자식을 에이전트가 찾으므로, 에이전트가 연결을 보지 못한 가지는 열리지 않는다. 결과가 확정된 전수가 아니라는 점을 보고에 한 줄로 밝힌다.
