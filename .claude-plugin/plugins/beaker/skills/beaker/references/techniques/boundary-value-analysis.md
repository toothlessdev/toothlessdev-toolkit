# Boundary Value Analysis

**분류** specification-based · **Coverage Item** 각 경계값

이 기법이 beaker 의 핵심입니다. implementation anchoring 이 가장 극적으로 드러나는 자리이기 때문입니다.

## 언제

순서 있는 도메인(수, 날짜, 길이, 개수)에 임계값이 있을 때. EP 를 했으면 거의 항상 뒤따릅니다.

## 규칙

명세가 지정한 임계값을 `T`, 비교 관계를 `R` 이라 하자. 파티션 경계마다 **결과가 갈리는 두 구간에 하나씩 걸치는** 두 값을 Coverage Item 으로 만듭니다. 한 값은 경계 바로 안쪽, 다른 값은 바로 바깥쪽입니다.

어느 쪽이 바깥인지는 `R` 이 정합니다. 결과 X 의 구간 안에 `T` 자체가 들어가느냐가 `R` 마다 다르기 때문입니다.

| R | `T` 는 X 구간 | 이산 도메인 | 연속 도메인 |
|---|---|---|---|
| `>=` (이상) | 안 | `T-1`, `T` | `T-ε`, `T` |
| `>` (초과) | 밖 | `T`, `T+1` | `T`, `T+ε` |
| `<=` (이하) | 안 | `T`, `T+1` | `T`, `T+ε` |
| `<` (미만) | 밖 | `T-1`, `T` | `T-ε`, `T` |

`ε` 는 표현 가능한 최소 간격입니다. `>` 와 `<=` 에서 `T-1` 을 고르면 두 값이 같은 구간에 놓여 경계 반대편의 오류를 놓칩니다.

2-value 를 기본으로 합니다. 명세가 그 경계를 특별히 위험하다고 지정하면 `T-1, T, T+1` 로 늘립니다.

도메인 양끝도 경계입니다.

```
CI: min(domain(paramA))
CI: max(domain(paramA))     타입이 상한을 주는 경우
```

## `T` 는 명세에서만 나온다

**이 기법에서 가장 중요한 규칙입니다.**

`T` 는 명세가 말한 값입니다. payload 어딘가에 다른 값이 보여도 그건 `T` 가 아닙니다. 구현의 임계값이 `T` 와 다를 수 있고, **그 불일치를 드러내는 게 이 테스트의 존재 이유입니다.**

```
명세의 임계값   T
구현의 임계값   T'        ← 너는 이걸 모른다. 알아도 쓰지 않는다.

경계를 T' 로 잡으면  →  T'-1, T' 를 테스트한다. 전부 통과한다. 아무것도 못 찾는다.
경계를 T  로 잡으면  →  T-1, T 를 테스트한다. 불일치 구간에서 실패한다.
```

`paramC = ?` 처럼 마스킹된 default value 를 보면 그건 leak 흔적입니다. 값을 추측하지 말고 `leakSuspects` 에 적으세요.

## 명세가 임계값을 안 줄 때

명세가 부류만 서술하고 `T` 를 주지 않으면 **경계를 발명하지 마세요.** 도메인 상식으로 그럴듯한 값을 채우면 아무것도 검증하지 않는 케이스가 됩니다.

`ambiguities` 에 `Ambiguity` 항목을 올립니다. `question` 에는 임계값이 명세에 없다는 사실을, `blockedCoverageItems` 에는 그것 때문에 케이스를 만들지 못한 커버리지 항목 id 를 적습니다. 커버리지 항목 자체는 `conditions` 에 남겨둡니다.

## 포함/배타를 정확히 읽어라

`이상` / `초과` / `미만` / `이하` — 관계 `R` 이 `>=` 인지 `>` 인지가 `T` 와 짝을 이룰 반대편 값이 `T-1` 인지 `T+1` 인지를 바꿉니다. 실무에서 가장 자주 틀리는 지점이고, 그래서 테스트할 가치가 가장 높은 지점입니다.

명세가 포함 여부를 분명히 하지 않으면 추정하지 말고 `Ambiguity` 입니다.

## 도출 흐름

<example>
명세 문장이 "paramA 가 `T` 이상이면 결과 X" 형태일 때.

```
Test Condition
  statement    paramA 의 임계값 경계에서의 결과 판정
  basisRefs    해당 명세 항목 id

Coverage Item ①
  technique    boundary-value-analysis
  description  paramA = <T 바로 아래 값> — 경계 바깥, 반대 결과

Coverage Item ②
  technique    boundary-value-analysis
  description  paramA = <T> — 경계, 명세가 지정한 결과 X

Test Case (Coverage Item 마다 1개)
  inputs       paramA 에 위 값, 나머지 파라미터는 유효 대표값
  expected     명세가 각 구간에 지정한 결과
  rationale    명세가 지정한 경계이고 반대편의 가장 가까운 값이라는 사실
```

`<T>` 자리에는 **명세에서 읽어낸 실제 값**이 들어갑니다. `T` 는 이 문서의 기호일 뿐 산출물에 쓰는 표기가 아닙니다.
</example>
