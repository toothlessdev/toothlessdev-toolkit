# 모핑 스토리보드

결과물은 코드가 아니라 표 하나입니다. 사용자가 이 표를 보고 흐름을 고칠 수 있어야 합니다.

`(example)` 이 붙은 내용은 뜻을 보여 주는 사례입니다. 도메인, 이름, 숫자를 새 덱에 옮기지 않습니다.

## 추상에서 디테일로

1. **전체 그림을 하나 정합니다.** 요소 3~5개로 전체 흐름이 보이는 추상 그림입니다. 이 그림이 덱 전체의 기준 화면이 됩니다.
2. **요소 하나를 골라 파고듭니다.** 그 도형이 쪼개지거나, 묶이거나, 안에 구조가 생겨 다음 단계의 도형이 됩니다. 화면 전체를 바꾸지 않습니다.
3. **다시 전체로 돌아옵니다.** 다음 요소로 넘어가기 전에 전체 그림으로 돌아오면 청중이 지금 위치를 압니다. 짧은 발표는 앞 시점으로 되감거나 마지막에 한 번만 돌아와도 됩니다.

같은 도형이 변해 가면 청중은 새 그림을 해석하지 않고 변화만 따라가면 됩니다. 장마다 새 그림이 뜨면 매번 처음부터 읽어야 합니다.

모핑은 앞 도형과 다음 도형의 관계로 고릅니다.

| 관계   | 앞 도형 → 다음 도형             | 설명되는 것             |
| ------ | ------------------------------- | ----------------------- |
| 쪼개짐 | 덩어리 하나 → 작은 단위 여러 개 | 하나가 여러 단위로 나뉨 |
| 묶임   | 작은 단위 여러 개 → 묶음        | 단위를 모아 함께 다룸   |
| 대응   | 묶음 → 그 묶음을 맡는 주체      | 묶음마다 맡는 쪽이 생김 |
| 열림   | 상자 → 상자 안 구성 요소        | 같은 상자 안을 들여다봄 |

(example) 조사 도구 덱: 파일 트리의 줄이 파일 박스로 쪼개지고, 파일 박스가 청크로 묶이고, 청크마다 에이전트 노드가 하나씩 생깁니다.

**라벨만 바꾸지 않습니다.** 상자 배치를 고정한 채 글자만 바뀌면 그림이 설명을 멈춥니다. 그림을 고정하는 것 자체는 괜찮습니다. 키마다 그 안에서 물건이 실제로 움직이면 됩니다.

**물건이 실제로 하는 일을 움직임으로 만듭니다.** 상자와 화살표로 때우지 않습니다. 도는 것은 돌고, 옮겨지는 것은 작은 조각으로 흘러가고, 쌓이는 것은 칸이 차오릅니다. 느린 일은 화면에서도 느리게 찹니다. 가능하면 설명대로 돌아가는 작은 시뮬레이션으로 만들어 차이가 눈에 그대로 나오게 합니다.

(example) 디스크 덱: 원판이 돌고, 읽은 데이터가 조각이 되어 메모리 칸으로 들어갑니다. 무작위 읽기는 헤드가 오가느라 칸이 느리게 찹니다.

**앞 도형을 지우고 있다면 멈춥니다.** 지우고 새로 그리는 대신, 그 도형이 무엇으로 바뀌는지 먼저 찾습니다. 그래도 이어지지 않으면 주제가 바뀌는 지점이니 끊어도 됩니다. 그때는 표에 끊는 이유를 적습니다.

## 페이지 모핑과 내부 구성요소 모핑을 나눕니다

키마다 둘 중 하나로 정하고 스토리보드에 적습니다. 같은 맥락 안에서 화면 전체가 바뀌면 앞 그림과 이어지지 않습니다.

- **내부 구성요소 모핑**: 물건의 자리와 크기를 유지하고 색, 조각 이동, 새 요소 추가만 일어납니다. 기본값입니다. 키 한 번에 변화 하나만 둡니다
- **페이지 모핑**: 물건의 자리나 크기가 거의 다 바뀝니다. 설명 대상이 바뀔 때만 쓰고 덱 하나에 1~2번으로 둡니다. 앞 그림의 물건이 뒤 그림의 물건으로 변형되어야 합니다. 없던 그림으로 건너뛰지 않습니다

| 설명 대상이 바뀌나 | 지금 그림에 자리가 있나 | 처리                                                |
| ------------------ | ----------------------- | --------------------------------------------------- |
| 아니오             | 있음                    | 내부 구성요소 모핑                                  |
| 아니오             | 없음                    | 첫 그림을 다시 배치합니다. 카메라로 때우지 않습니다 |
| 예                 | 있음                    | 내부 구성요소 모핑, 나머지를 흐리게 합니다          |
| 예                 | 없음                    | 페이지 모핑                                         |

이 구분을 지키려면 첫 그림을 이렇게 잡습니다.

- **한 화면에 전부 넣습니다.** 안 들어가면 카메라를 쓰는 대신 도형 크기나 줄 수를 줄입니다. 기본 도형의 짧은 변은 16:9(1600x900) 무대에서 26~40px, 9:16(1080x1920) 무대에서 70~110px 가 기준입니다. 세로 무대는 휴대폰에서 약 0.36배로 줄어 보이기 때문입니다
- **나중에 나올 물건의 자리를 비워 둡니다.** 설명과 수치가 들어갈 자리를 처음부터 잡아 둡니다. (example) 그림 오른쪽에 비워 둔 세로 열
- **강조는 확대 대신 나머지를 흐리게 합니다**
- **전체에 걸치는 효과도 그림 안에서 냅니다.** 화면 전체를 바꾸지 않고, 영향을 받는 요소만 바꿔서 무엇이 남는지 보이게 합니다. (example) 정전을 보여 줄 때 화면을 끄지 않고 휘발되는 칸만 끕니다

### 세로(9:16) 무대

`deck:deck` 에서 9:16 으로 정했으면 첫 그림을 이렇게 잡습니다.

- **위아래로 쌓습니다.** 가로 무대의 왼쪽과 오른쪽 구역을 위와 아래 구역으로 바꿉니다. 두 구역을 넘기지 않습니다. (example) 위는 코드, 아래는 그 코드가 다루는 메모리 그림
- **아래쪽 약 20% 는 비워 둡니다.** 자막과 재생 바가 덮는 자리입니다. 음성판을 만들지 않아도 휴대폰 화면 아래에는 앱 조작 영역이 겹칩니다
- **장 수를 줄입니다.** 1~2분 영상이면 키 8~10번 안에 끝냅니다. 한 키에 변화 하나라는 규칙은 그대로입니다
- **제목은 두 줄 안에 끝냅니다.** 무대 폭이 좁아 세 줄이 되면 그림 자리를 먹습니다

## 애니메이션은 동작을 보여 줍니다

판단 질문은 하나입니다. **이 애니메이션을 빼면 설명도 같이 사라지는가?** 안 사라지면 장식입니다.

- 장식: 글자나 카드가 차례로 나타나기만 합니다
- 동작: 설명하는 일이 화면에서 일어납니다. 구조가 자라고, 값이 바뀌면 결과가 함께 바뀌고, 상태가 실제 조건에서 바뀝니다

(example)

| 설명할 내용                | 장식 (쓰지 않음)     | 동작 (씀)                                |
| -------------------------- | -------------------- | ---------------------------------------- |
| 에이전트가 에이전트를 스폰 | 카드가 차례로 나타남 | 트리가 자라며 노드가 켜짐                |
| 묶음 크기 설정             | 값이 적힌 문구 등장  | 값을 움직이면 묶음과 담당 수가 함께 바뀜 |
| 대화가 안 끝남             | 말풍선 카드 등장     | 입력창에 쳤다가 지우기를 반복            |

글자와 카드가 하나씩 떠오르기만 하는 장은 그림이 빠진 것입니다. 문장 하나로 끝나는 질문 장은 움직임 없이 두어도 됩니다. 효과를 억지로 넣지 않습니다.

구조를 다 쌓은 뒤에는 **실제 요청 흐름을 그 그림 위로 흘립니다.** 어디로 들어가서 어디로 퍼지는지가 움직임으로 보여야 합니다.

## 새 그림으로 빼지 않습니다

자세한 설명, 요청 흐름, 장애 상황은 별도 그림이 아니라 지금 그림 안에서 보여 줍니다. 내부를 설명할 때는 그 상자를 열어 안을 보여 줍니다.

**헷갈리는 질문도 같은 그림의 다음 단계로 넣습니다.** 사용자가 대화 중에 물은 질문이나 청중이 할 법한 질문을 답변 글로 끝내지 않고, 그 질문이 가리키는 상황을 그림 위에서 재생합니다.

(example) "quorum 이면 쓰기가 여러 서버로 나뉘는 거 아냐?" 라는 질문에는 쓰기 여러 건이 실제로 어느 서버를 지나는지 같은 그림에서 재생합니다.

## 그림에 드러나야 할 것

글자를 읽기 전에 그림만 봐도 아래가 보여야 합니다. 스토리보드에 어떤 도형으로 보여 줄지 적습니다.

- **종류 구분**: 역할이 다른 요소는 아이콘과 모양으로 구분합니다. 이름 글자에만 기대지 않습니다. (example) 서버와 저장소
- **어디서 읽고 어디에 쓰나**: 데이터가 어디 있고 누가 어디서 가져오는지 위치와 화살표로 보입니다. 공유하는 것을 각자 따로 가진 것처럼 오해하지 않게 합니다
- **물리적 경계**: 나뉘어 있는 경계를 그림 안에 그립니다. (example) 가용 영역, 리전, 프로세스, 커널과 사용자 공간
- **용어와 도형 연결**: 새 용어는 이미 그림에 있는 도형에 붙여 설명합니다. 새 용어를 위한 새 그림을 띄우지 않습니다
- **상자 안의 관계**: 무엇끼리 복제되는지, 데이터가 어떻게 놓이는지 보입니다. 같은 것끼리 같은 색으로 묶습니다

## 숫자와 개념을 구분합니다

그림에 나오는 숫자와 개념마다 아래 답을 스토리보드의 "발표자가 하는 말" 칸이나 그림에 넣습니다.

| 물을 것                      | 답에 넣을 내용                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| 이 숫자는 바꿀 수 있나       | 고정값, 설정값, 설명용 예시 중 무엇인지와 근거가 언제 기준인지                      |
| 왜 나누나                    | 나누는 이유와 나누는 기준. 비슷한 말이 어디에 적용되는지. (example) 파티셔닝과 샤딩 |
| 다른 곳의 같은 이름과 같은가 | 같은 이름을 쓰는 다른 시스템과 무엇이 같고 다른지                                   |
| 내가 아는 무엇에 가깝나      | 청중이 아는 개념과의 비교와, 어디까지 같고 어디서 다른지                            |

## 발표자가 말하는 마디로 나눕니다

발표자는 말하면서 넘깁니다. 그래서 단계는 그림 기준이 아니라 **말의 마디** 기준으로 나눕니다.

- 설명할 항목이 여러 개면 키 한 번에 하나씩 바뀌게 합니다. 여러 요소가 한 번에 바뀌면 말할 틈이 없습니다
- 말하는 동안 틀어 둘 장면은 끝없이 도는 루프로 표시합니다
- 첫 키를 누르기 전에 설명할 말이 있는 장은 대기 상태로 시작합니다

## 전개 순서

구조를 다 쌓은 덱은 대개 이 순서로 갑니다. 단계를 건너뛰어도 되지만 순서는 바꾸지 않습니다.

1. **추상**: 전체 그림 하나와 흐름 한 번
2. **구조 쌓기**: 요소를 하나씩 열거나 쪼갭니다
3. **요청 흘리기**: 쌓은 구조 위로 실제 요청을 흘립니다. 새 도형은 거의 없습니다
4. **오해 풀기**: 청중이 할 법한 질문을 같은 그림에서 재생합니다
5. **부수고 복구**: 장애를 넣어 무엇이 멈추고 무엇이 살아남는지 보여 줍니다
6. **다음 규모**: 지금까지의 그림 전체를 다음 단계의 부품으로 만듭니다. 덱의 페이지 모핑은 대개 여기서 한 번입니다

함께 지키는 것:

- **제목은 결론 문장입니다.** 명사가 아니라 그 단계에서 알게 되는 사실을 씁니다. 본문은 두 문장 이내입니다. (example) "Segment 구조" 대신 "볼륨은 10GB 단위 segment 로 잘린다"
- **숫자는 움직이며 설명합니다.** 조건을 글로 쓰지 않고, 카운터가 조건에 닿는 순간 결과가 일어나게 합니다. (example) "6개 중 4개면 커밋" 을 쓰지 않고 카운터가 4/6 이 되는 순간 커밋 토큰이 돌아옵니다
- **앞 단순화를 밝힙니다.** 앞에서 단순하게 그린 부분을 고칠 때는 단순화였다고 말하고 같은 그림을 고칩니다

(example) Aurora 쓰기 경로 덱의 14단계

| 단계  | 전개        | 제목                                                     | 도형에 일어나는 일                                    |
| ----- | ----------- | -------------------------------------------------------- | ----------------------------------------------------- |
| 1     | 추상        | SQL 을 처리하는 서버와 데이터를 저장하는 볼륨으로 나뉜다 | 서버 2개, 볼륨 1개. 로그와 페이지가 한 번 흐름        |
| 2~6   | 구조 쌓기   | AZ, segment, replica, 페이지 배치, full 과 tail          | 볼륨이 넓어지고 띠가 replica 6개로 쪼개짐             |
| 7~9   | 요청 흘리기 | INSERT 한 건의 락, 4/6 확인, Reader 캐시                 | 토큰이 날아가고 카운터가 0/6 에서 4/6 으로 오름       |
| 10    | 오해 풀기   | quorum 이어도 쓰기는 Writer 한 대를 지난다               | INSERT 7건이 전부 Writer 를 지남                      |
| 11~13 | 부수고 복구 | AZ 장애, 쓰기 멈춤, replica 교체                         | AZ 하나가 빨개지고 카운터가 3/6 에서 멈춘 뒤 6/6 복귀 |
| 14    | 다음 규모   | 쓰기를 늘리려면 이 그림 전체를 나눠야 한다               | 그림이 반으로 줄고 복제되어 샤드 2개가 됨             |

## 결과물

아래 열을 가진 표를 파일이나 응답으로 내고 사용자 확인을 받은 뒤 구현으로 넘어갑니다.

| 열                     | 적는 것                             |
| ---------------------- | ----------------------------------- |
| 장                     | 장 번호                             |
| 지금 보이는 도형       | 이 키를 누르기 전 화면의 도형       |
| 키 또는 재생           | 키 번호, 또는 자동 재생 시간        |
| 전환 종류              | 페이지 모핑 또는 내부 구성요소 모핑 |
| 무엇이 무엇으로 바뀌나 | 앞 도형과 다음 도형                 |
| 발표자가 하는 말       | 그 키에서 할 말 한두 문장           |

(example)
