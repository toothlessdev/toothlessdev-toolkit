# 장표 움직임 구현

`(example)` 이 붙은 내용은 뜻을 보여 주는 사례입니다. 도메인, 이름, 숫자를 새 덱에 옮기지 않습니다.

## 먼저 볼 규칙의 예외

`animate`, `emil-design-eng` 의 곡선 값과 `transform` · `opacity` 우선, `prefers-reduced-motion` 대응은 그대로 따릅니다. 다만 두 규칙은 덱에 적용하지 않습니다.

- **"UI 애니메이션은 300ms 이하"**: 하루 수백 번 쓰는 UI 기준입니다. 덱은 설명이 목적이라 더 길어도 됩니다
- **"키보드로 부른 동작은 애니메이션 금지"**: 같은 이유입니다. 다음 단계로 넘기는 키는 모핑을 시작하는 것이 맞습니다

## 모핑

구현 패턴(장면 함수, 같은 요소 이동, 겹쳐서 모핑, 카메라)은 [references/morph.md](references/morph.md) 에 있습니다. 모핑을 구현하기 전에 읽습니다.

전환은 `deck:story` 의 페이지 모핑과 내부 구성요소 모핑 구분을 따릅니다. 카메라로 화면 전체를 옮기지 않습니다. 카메라 패턴은 페이지 모핑에서 그림 전체를 줄이는 경우에만 씁니다.

## 속도와 자연스러움

읽어야 하는 움직임은 읽을 수 있어야 하고, 상태 변화는 번져 나가야 합니다. 아래 값은 출발점이고, 재생해 보고 조정합니다.

| 움직임                  | 기준                                           | 이유                                                 |
| ----------------------- | ---------------------------------------------- | ---------------------------------------------------- |
| 목록 스크롤             | 초당 약 18줄 이하                              | 지나가는 글자를 읽을 수 있어야 함                    |
| 많은 요소의 색 변화     | 요소당 약 420ms, 전체 약 1.5초에 걸쳐 순서대로 | 변화가 번지는 방향이 보여야 함                       |
| 내부 구성요소 위치 모핑 | 700~1200ms, `cubic-bezier(0.77, 0, 0.175, 1)`  | 화면 안 이동이라 ease-in-out                         |
| 페이지 모핑             | 요소마다 약 1.2초, 전체 2~3초에 걸쳐 순서대로  | 어느 물건이 어디로 가는지 눈으로 따라갈 수 있어야 함 |
| 등장                    | 420~560ms, `cubic-bezier(0.23, 1, 0.32, 1)`    | 들어오는 움직임이라 ease-out                         |
| 타이핑                  | 글자당 60~110ms, 말 끝에서 약 900ms 멈춤       | 멈춤이 있어야 읽힘                                   |
| 바뀌는 자막             | 한 문장을 3초 이상 유지                        | 읽기 전에 사라지면 없는 것과 같음                    |

**시각을 절대값으로 흩뿌리지 않습니다.** 앞 구간 길이를 바꾸면 뒤의 모든 시각이 밀립니다. 구간 길이를 상수로 두고 뒤 구간은 그 상수에서 계산합니다. 속도는 숫자 하나로 고칠 수 있어야 합니다.

## 발표자 진행

- **장 이동은 `#s번호` 해시를 지원합니다.** 재생 확인 도구가 이 규칙으로 장을 엽니다. 장 수는 `window.DECK_STEP_COUNT` 로 알리고, 없으면 도구가 `.slide` 요소 수를 셉니다
- **무대 크기는 `window.DECK_STAGE_SIZE = { width, height }` 로 알립니다.** 재생 확인 도구가 이 값으로 화면 크기를 맞춥니다. 페이지를 읽자마자 정해지도록 스크립트 맨 위에서 넣습니다. 없으면 도구는 1600x900 으로 봅니다
- **입력**: `→`, 스페이스, 클릭은 다음 단계입니다. `←`, 화면 왼쪽 클릭은 이전 단계입니다
- **단계가 남았으면 장을 넘기지 않습니다.** 마지막 단계 다음에야 다음 장으로 갑니다
- **조작 UI를 화면에 두지 않습니다.** 노트, 전체 화면, 다시 재생은 키로 둡니다(`N`, `F`, `R`)
- **발표 노트는 각 장에 숨겨 둡니다.** 발표자가 말할 문장을 씁니다

단계 상태는 **단계 번호에서 화면을 계산하는 함수**로 만듭니다. 앞으로 갈 때 누적해서 바꾸면 뒤로 갈 때 복원이 틀어집니다.

(example) 질문 카드가 단계마다 하나씩 답 상태가 되는 장

```js
function renderStep(stepIndex) {
    cards.forEach(function (card, index) {
        card.classList.toggle("is-answered", index < stepIndex);
    });
}
```

장 안 단계와 장 이동은 이렇게 나눕니다. `stepForward` 는 단계를 소비했으면 `true`, 남은 단계가 없으면 `false` 를 돌려줍니다. `stepBack` 도 같습니다.

```js
function advance() {
    if (activeScene && activeScene.stepForward && activeScene.stepForward())
        return;
    showSlide(currentSlideIndex + 1);
}
```

**반복 재생 안에서 거는 타이머는 단계 종료 판정에서 뺍니다.** "아직 진행 중인 움직임이 있으면 키는 그 움직임을 끝내는 데 쓴다" 는 규칙을 쓰는 덱에서, 루프가 계속 거는 타이머까지 진행 중으로 세면 키가 영원히 다음 단계로 넘어가지 않습니다. 루프용 타이머와 일회성 움직임을 구분해 둡니다.

iframe 안에 넣어 공유한다면 `history.replaceState` 를 try/catch 로 감쌉니다. 막혀도 슬라이드 넘김은 살아야 합니다.

## 재생 확인

**`--timeout`, `--virtual-time-budget` 로 찍지 않습니다.** `requestAnimationFrame` 과 transition 프레임을 제대로 못 찍어서 멀쩡한 장이 깨져 보이거나 깨진 장이 멀쩡해 보입니다. 실제 시간으로 재생해 찍는 도구를 씁니다.

```bash
node ${CLAUDE_PLUGIN_ROOT}/skills/motion/scripts/capture.mjs <deck.html> <저장 폴더> '<계획 JSON>'
```

계획 JSON 은 항목 배열입니다.

- `{"slide": <장 번호>, "at": [<ms>, …]}`: 장을 연 뒤 그 시각에 찍습니다. 로드 대기 약 0.9초가 지난 뒤부터 세므로 진입 모핑 중간은 안 찍힙니다. 모핑 중간은 `at` 으로 재생을 끝낸 뒤 `keys` 와 짧은 `keyWaitMs` 로 찍습니다
- `{"slide": <장 번호>, "keys": [<키>, …], "keyWaitMs": <ms>}`: 키를 하나씩 누르고 `keyWaitMs` 뒤 찍습니다. 앞뒤 단계와 복원을 이걸로 확인합니다
- `{"slide": "all", "at": [<ms>]}`: 모든 장을 같은 시각에 찍습니다
- `{"walk": <횟수>, "keyWaitMs": <ms>}`: 1장부터 다음 키를 그 횟수만큼 누르며 단계마다 찍습니다. 키로 진행하는 덱은 이걸로 뒷단계까지 봅니다
- `"name"`: 파일 이름 앞에 붙습니다. 같은 장을 두 번 찍을 때 씁니다

(example)

```bash
node ${CLAUDE_PLUGIN_ROOT}/skills/motion/scripts/capture.mjs deck.html shots '[{"slide":3,"at":[1500,6000]},{"slide":5,"keys":["ArrowRight","ArrowLeft"],"keyWaitMs":700},{"walk":30,"keyWaitMs":1500}]'
```

- 화면 크기는 덱의 `window.DECK_STAGE_SIZE` 를 따릅니다. 세로 덱은 1080x1920 그대로 찍힙니다
- 끝나면 찍은 사진을 모은 `contact.jpg` 를 만듭니다. 장 사이 밀도와 흐름은 이 한 장으로 먼저 봅니다
- 실제 시간으로 재생하므로 덱 전체를 찍으면 몇 분 걸립니다. 백그라운드로 돌립니다
- 스크립트 오류는 `errors` 로 출력되고, 있으면 종료 코드가 1입니다

사진은 직접 열어 봅니다. `errors: []` 는 스크립트가 안 죽었다는 뜻이지 그림이 맞다는 뜻이 아닙니다. 시작, 모핑 중간, 끝을 각각 찍어 도형이 정말 이어지는지 봅니다.

## 키마다 화면이 얼마나 바뀌나

구현이 끝나면 키 한 번에 그림 영역 픽셀이 얼마나 바뀌는지 잽니다. 내부 구성요소 모핑은 대개 15% 이하이고, 30% 를 넘는 키는 스토리보드에서 페이지 모핑으로 정한 키여야 합니다.

```bash
UV_NATIVE_TLS=1 uv run ${CLAUDE_PLUGIN_ROOT}/skills/motion/scripts/key_change.py <deck.html> --keys <누를 키 횟수> --wait-ms <키마다 기다릴 ms>
```

- `--keys`: 누를 키 횟수입니다. 보통 덱의 전체 키 수입니다. 표지 전환은 값이 커도 무시합니다
- `--wait-ms`: 키마다 움직임이 끝나기를 기다리는 시간입니다. 가장 긴 모핑보다 길게 둡니다. 실제 시간으로 재생하므로 덱 하나에 몇 분 걸립니다
- `--clip x,y,w,h`: 잴 영역입니다. 기본값은 무대 높이의 위 약 14% (제목)와 아래 약 12% (캡션)를 뺀 그림 영역입니다. 무대 크기는 capture.mjs 와 같이 `window.DECK_STAGE_SIZE` 에서 읽습니다. 세로 덱처럼 제목이 길거나 아래를 자막 자리로 비웠으면 직접 지정합니다

화면 전체에 걸치는 효과나 시뮬레이션 재시작도 수치를 올리므로, 수치는 합격선이 아니라 다시 볼 곳을 찾는 신호로 씁니다.
